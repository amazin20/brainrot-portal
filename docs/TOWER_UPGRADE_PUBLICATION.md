# Публикация обновления уровня 41

Обновление публикуется в существующей игре
`https://amazin20.github.io/brainrot-portal/`. Уровень 41 выбирается в обычном
меню или через `?edition=foundation&level=41`. Каталог `tower-singularity/`
сохраняет существующую постоянную ссылку и страницу непрерывного прохождения.
Он содержит ту же проверенную сборку, что и основной адрес игры.

## Единственный действующий путь публикации

1. Точный исходник размещается в ветке `upgrade/tower-41-final`.
2. `tower-upgrade.yml` независимо проверяет весь действующий набор исходных
   регрессий, три редакции сохранённой кампании и происхождение старого
   опубликованного пакета. Все эти задания должны завершиться успешно.
3. Задание `candidate` строит этот же коммит, проверяет состав пакета,
   настоящий WebGL, полный маршрут башни, высокий профиль графики, сохранённые
   комнаты и управление на компьютере и двух мобильных разрешениях. Затем
   записывает одно непрерывное прохождение и сохраняет точную сборку.
4. В `main` закреплены конфигурация релиза и однократный автоматический
   запуск публикации после успешного завершения проверки `37142162076`
   коммита `019c7195bf83dc29acaf09aeff7ae15f13431fa7`. События другой
   ревизии или неудачной проверки не запускают публикацию. Все проверки
   артефактов повторно выполняет `publish-singularity-upgrade.yml`.
5. Публикация переносит проверенные байты в основной каталог, сохраняет
   модели, Draco, сорок ранее утверждённых видео и их записи в галерее.
   Только финальная запись галереи получает новое прохождение уровня 41.
6. После развёртывания проверяются публичные хеши, обычное меню и Play,
   мобильная пауза, перезапуск и повторная загрузка, ссылка финального уровня,
   вся сохранённая галерея и переходы по новому видео.

Исторический `deploy-pages.yml` больше не запускается от `push` в `main`:
его контракт относится к заменённой башне из восемнадцати крыльев. Это
исключает вторую автоматическую публикацию той же ветки.

Исходные регрессии и матрицы кампании работают параллельно. Полный набор
проверок не сокращён, а длительный набор исходных тестов больше не ожидает
завершения трёх матриц перед своим запуском.

## Закреплённая конфигурация релиза

Файл создаётся только после успешного запуска окончательного исходника:

```json
{
  "mode": "complete",
  "sourceCommit": "<SHA из сорока шестнадцатеричных символов>",
  "candidateRun": 0,
  "baseCommit": "a74726ff1bfb22f21662d076fc47951b2bf368cd",
  "baseRun": 36509639087,
  "previousSourceCommit": "b1bf88fb90b85e3b0786c651fcd2ba2edcf92696",
  "previewPath": "tower-singularity"
}
```

`candidateRun: 0` и строка-заполнитель показаны только как схема: workflow
отклоняет их. Подставляются фактические SHA и номер успешного запуска.
`baseRun` подтверждает первоначальную публикацию кампании; сохранённый архив
для сборки релиза берётся из `candidateRun`, где он прошёл повторную проверку.
Состояние уже опубликованной игры проверяется перед развёртыванием, чтобы
не перезаписать чужое более новое обновление.
