## Сохранения: четыре действительных стадии

Shared `preferenceLifecyclePureValidator:true` требуется и от SOURCE, и от PUBLIC. Source Root отдельно связывает реальные runtime preferences с DOM; bare PUBLIC использует только настоящие DOM-наблюдения, write log и исходные байты private JSON после обычного действия, без синтеза скрытых runtime preferences.

| Стадия | Фаза и фактическое наблюдение |
|---|---|
| `initial` | `historical-read-through`: `ownRaw:null`, `ownPreferences:null`, `writes:[]`. Валидный v61 save читается без startup write; реальный DOM показывает 13 завершений и начальные настройки. PUBLIC не заявляет начальное наблюдение hints через скрытый runtime. |
| `settings` | Обычные действия volume/tutorial создают private v62 JSON; фаза `own-persisted`, volume 0,37, tutorial выключен. В фактической записи сохранены 13 завершений, 5 hints и принятые room revisions. |
| `playing` | Настоящий Play сохраняет выбранную комнату и тот же private JSON; фаза `own-persisted`, наблюдаются только `setItem` точного v62 preference key. |
| `reloaded` | Reload читает сохранённую private запись, сохраняя прогресс, hints и настройки; фаза `own-persisted`. Новый write на reload не требуется. |

Исторические raw save-байты остаются неизменными. Это конечная проверка жизненного цикла валидного сохранения, не заявление о всех возможных повреждённых записях.
