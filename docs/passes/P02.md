## Asset / mechanism contract

Two bolted mechanical load instruments use the same embossed weight/support pictogram and broad moving pointer. One mounts on the receiver's existing solid side casing, the other on the cassette's existing solid upper side. A single continuous sheathed control cable connects the housings, with ferrules and receiver-side clamps. The suspended part stays above the starting gallery and outside the flight windows. It is not an additional walkable beam.

The contact comes from `seat.loaded()`, the same supported-cargo predicate used by the actuator. Hand-held, hovering and out-of-tray cargo do not indicate load. Both pointers agree regardless of the brake: load indication is NOT an assertion that the cassette is moving. The model visualizes a load command for the already documented kinematic actuator; it is not claimed as an energy-conserving simulation of a remote cable, scale or hydraulic circuit. No false compression of the stationary collision floor is drawn.

The display uses time-based exponential response in fixed updates and interpolation for rendering. Render-only calls cannot advance its state; restart clears residual indication. It owns no listeners, textures, physics bodies or separate global cache. Existing room resource disposal owns its meshes/materials.

Editable source and material names: `src/game/LabPocketLoadLink.js`. Runtime parameters: two mounting poses, cable control points, indicator sweep 1.74 radians, response rate 12/s. Current model: **5 meshes, 3 materials, 5,532 triangles, 0 textures**. Static detail is batched by material; only the two pointers remain separate. No new external GLB download is required by the game. `node scripts/export-pocket-load-link.mjs` optionally exports the same factory for review, under 4 MB. The script does not pretend to be a full glTF Validator or export runtime-driven animation clips.
