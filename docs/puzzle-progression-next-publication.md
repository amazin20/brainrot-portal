# Проверка и публикация пространственных испытаний 47–49

Статус этого документа — схема проверки, а не свидетельство её прохождения. Ветка `upgrade/puzzle-progression-next-20261009` должна быть зафиксирована отдельным исходным коммитом после завершения комнат. Новый маршрут доступен только в opt-in сборке: `/puzzle-progression-next/?edition=foundation&level=47&pilot=progression`. Сохраняются комнаты 43–49; свежие браузерные проверки и фильмы относятся строго к 47–49. Сохранения новой серии используют `brainrot-puzzle-progression-next-v1:`.

- Основа опубликованного сайта: publisher `edb11aecfeb634b62addba95e2898cfca0799a79`, успешная публикация `37889948751`, попытка 1. Сохраняются все 1378 файлов и 501 388 060 байт, включая основную кампанию, пилот 43 и серию 44–46.

## Свежая проверка исходников

`.github/workflows/puzzle-progression-next-review.yml` выполняет ровно семь jobs: `build`, `cpu`, `native (47)`, `native (48)`, `native (49)`, `package`, `gate`. `build` один раз выполняет `npm ci`, строит и инвентаризирует production пакет. После него CPU (полный активный набор тестов, лимит 60 минут) и три native jobs запускаются параллельно. Native jobs скачивают единственный пакет; они не пересобирают игру. Каждый job пишет маркер точного исходного SHA, run ID и попытки.

Native проверка выполняет обычный маршрут с оригинальными моделями и физическим телом спутника, наблюдает идентичность моделей на каждом кадре, запрещает reset/respawn внутри маршрута, проверяет совместную победу и настоящие действия «Следующий уровень», повтор, пауза. Одна штатная инициализация до первого кадра явно записана. Мобильная проверка использует отдельную вкладку с emulated touch, coarse pointer и окном 390×844. Настоящие CDP/touchscreen события запускают игру, двигают джойстик и исходного игрока, поднимают его прыжком, переключают бег, приостанавливают и возобновляют игру; проверяется освобождение джойстика. Отчёт обязан содержать реальные input/позиции/дистанцию и высоту прыжка, а также неизменность прежних сохранений 44–46. Это ограниченная проверка управления в эмуляции, а не FPS или приёмка всех действий на физическом телефоне.

Три непрерывных MP4 записываются обычными входными действиями в том же пакете при 640×360 и 4 кадрах/с. Каждый итоговый файл полностью декодируется FFmpeg с `-xerror`; ffprobe подтверждает кадры, длительность и кодек. Эти фильмы показывают маршрут, а не человеческое время поиска решения или производительность устройства.

`package` допускает только отчёты, фильмы и CPU receipt одного SHA/run/attempt. SHA-256 таблицы игровых файлов одинаков в каждом native и movie receipt. `gate` распаковывает сохранённый точный Pages ZIP/TAR безопасно и собирает весь сайт с добавлением нового каталога. Он не публикует сайт.

## Контроллер публикации

Подготовленный шаблон `publish-progression-next-controller.pending.yml` находится вне репозитория. Его `PENDING_EXACT_REVIEW` и нулевые ID намеренно блокируют публикацию. Только после успешной проверки всех семи jobs нужно вписать точный source SHA, source review run ID и текущую попытку, затем добавить единственный файл `.github/workflows/publish-puzzle-progression-next.yml` в `main` поверх принятого publisher. Игровые исходники в `main` не сливаются.

Перед сборкой и непосредственно перед deploy контроллер проверяет свежие source/main refs, ровно семь успешных jobs и их точные маркеры, checksum артефактов, ограниченную цепочку однофайловых контроллеров, отсутствие чужой текущей Pages публикации и последний принятый Pages deployment. Основная кампания (`8d2c01eacd86fe9235a35e7ec5f624ba62c3b29e`), пилот (`415b2da2cfe162fa9bf8f55803977ba2b5dd9bb6`) и серия 44–46 (`3aa725337737979ebd1fa6a4bb18b49d809e27fd`, review `37886420411/1`) имеют отдельные публичные проверки метаданных.

Непосредственно перед deploy проверяются SHA-256 и размер каждого из 1378 существующих публичных файлов. После deploy проверяется каждый старый и каждый новый файл по собранному manifest, затем повторяются три настоящих публичных native маршрута 47–49. Итоговая публикация считается принятой только после фактического успешного завершения обоих jobs контроллера, положительных PRE/POST byte receipts и трёх публичных отчётов этой исходной версии.

## Проверки самого конвейера

`node scripts/test-publish-puzzle-progression-next.mjs` атакует SHA/run/attempt, неполные jobs, заменённые пакеты, чужой контроллер, устаревшие refs, истёкший или изменённый архив, параллельные Pages deployments, метаданные сохранённых версий и reset/respawn/неполное наблюдение моделей. `python3 scripts/test-publish-puzzle-progression-next.py` проверяет безопасные ZIP/TAR пространства имён, traversal, ссылки, дубли, коллизии, пределы размеров, неизменность всех байтов принятого сайта, точные фильмы, разные scope playable/reviewed и свежие публичные receipts. Искусственные файлы fixtures никогда не являются свидетельством прохождения игры.
