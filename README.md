# БРЕЙНРОТ ПОРТАЛ

Браузерная 3D-головоломка от третьего лица: исследуйте пространство, направляйте скорость через порталы и доставляйте того же физического брейнрота к выходу. Оригинальные модели персонажей сохранены.

[Играть в браузере](https://amazin20.github.io/brainrot-portal/)

## Текущий проход разработки

В рабочей ветке подготовлен **v37 — кандидат с комнатой 21 «Гравитационный карман»**. Публичная ссылка выше остаётся версией `main`; наличие этой записи не означает публикацию кандидата. База: v36 и проверенные исправления управления из PR №29.

Новая комната разводит высоту падения и направление выхода: свободный груз проходит низкий проём и своей нагрузкой убирает защитную створку, игрок использует верхний край и наклонный выход. Постоянная приёмная галерея даёт ракурс для извлечения того же спутника. Разведка и грузовая подготовка допускают оба порядка; нижний обход возвращает после промаха. Паспорт, отличия от концепции и ограничения — в [docs/W03_GRAVITY_POCKET.md](docs/W03_GRAVITY_POCKET.md).

В каталоге рабочей ветки 21 комната. Принятые постановки 1–20 и исходные модели персонажей не переделаны. Графическая основа v36 применяется к новой комнате; её створка получила отдельную воспроизводимую модель с независимой коллизией. Сложность для незнакомого с решением игрока и производительность на физических устройствах пока не подтверждены.

## Управление

WASD — движение; мышь — камера; ЛКМ/ПКМ — синий/янтарный портал. E — взять или отпустить брейнрота, взаимодействовать с доступным объектом. Space — прыжок; Shift — бег; V — помахать рукой. Escape открывает паузу и выбор комнаты. После продолжения нажмите на сцену, чтобы захватить мышь. Есть сенсорное управление.

Светлые керамические плиты принимают порталы, тёмные конструкции — нет. Высота падения и направление портальной поверхности определяют дальнейший полёт. Брейнрот должен физически добраться вместе с игроком.

## Разработка и проверка

Node.js 22, Vite, Three.js и cannon-es. `npm ci` устанавливает зафиксированные зависимости; `npm run dev` запускает разработку. `npm run check` выполняет тесты и производственную сборку; `npm run preview` открывает собранный `dist`.

`node scripts/v8-journey.mjs` выполняет маршруты активной кампании обычными игровыми командами. Проверки обходов и восстановления отделены от успешных прохождений. Браузерные проверки выполняются в GitHub Actions с настоящей WebGL-сценой; доказательства включают игровые кадры. После публикации проверяется точный commit в публичном `build-info.json`.

Черновик для Яндекс Игр собирается командой `npm run build -- --mode yandex --outDir dist-yandex`. Проверка SDK с заглушкой не подтверждает настоящие рекламные показы или модерацию. В обычном интерфейсе нет кнопки подсказок и FPS; диагностический режим сохраняет инструменты проверки.

Старые заметки в `docs/` описывают соответствующие исторические версии. Они не являются перечнем активных комнат. Конечные автоматические проверки не доказывают отсутствие всех возможных обходов, субъективную сложность или FPS на устройстве игрока.
